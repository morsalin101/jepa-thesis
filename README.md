# Domain-specific I-JEPA for polyp segmentation

Self-supervised pretraining of a ViT on ~99k unlabeled GI endoscopy frames
(**HyperKvasir**), fine-tuned for polyp segmentation on **Kvasir-SEG**, compared
head-to-head against **MAE**, **SimCLR** and **MoCo v3** under an identical compute
budget. Everything runs on Kaggle's free GPU tier.

The I-JEPA implementation is faithful to
[facebookresearch/ijepa](https://github.com/facebookresearch/ijepa) and is verified
against it numerically — loading the official weights into this code reproduces its
loss exactly (see *Verifying faithfulness* below).

---

## Why this design

**Kvasir-SEG has 1000 images**, which is nowhere near enough to pretrain a ViT with SSL
(official I-JEPA uses ImageNet-1k's 1.28M). So pretraining runs on HyperKvasir's 99,417
*unlabeled* frames — same domain, no labels — and only the fine-tuning stage touches
Kvasir-SEG's labels. That separation is what makes the comparison meaningful and is the
novelty claim: a domain-specific JEPA for endoscopy, measured against the alternatives on
equal terms.

**Kaggle's free tier is ~30 GPU-h/week with a ~9h session cap.** The full program is
~75 GPU-h, so every pretraining run is chopped across sessions and must resume exactly.
That constraint shapes `src/utils/checkpoint.py`, `src/utils/kaggle_io.py` and the
session guard in the training loop.

```
  model/          vit, predictor, jepa | mae, simclr, mocov3 | simple_fpn, segformer_head, unet

  engine/         pretrain.py (all 4 methods), segment.py
  eval/           metrics (native-res), stats (Wilcoxon + BCa), tables, probe
  viz/            all thesis figures
  utils/          schedulers, checkpoint, ddp, kaggle_io

notebooks/        one Kaggle notebook per job, generated by build_notebook.py
reference/ijepa/  read-only clone of the official repo (gitignored)
```

## Running it

Order matters: data prep → pretrain (×4) → segment → analysis.

```bash
python3 scripts/build_notebook.py --user <kaggle-username>
kaggle kernels push -p notebooks/data-prep        # CPU session — free
kaggle kernels push -p notebooks/pretrain-ijepa   # GPU T4 x2
# ... pretrain-mae, pretrain-simclr, pretrain-mocov3
kaggle kernels push -p notebooks/segment
kaggle kernels push -p notebooks/analysis
```

Or run any stage directly:

```bash
python3 -m src.engine.pretrain --method ijepa --ckpt-slug <user>/jepa-thesis-ckpt
python3 -m src.engine.segment  --encoder ijepa --seed 0
python3 -m src.eval.stats
python3 -m src.eval.tables
python3 -m src.viz.make_all
```

**Resuming.** A pretraining notebook that prints `N epochs remaining` has stopped at the
session guard, not failed. Re-run the same notebook; it restores model, EMA target,
optimizer, GradScaler and schedule position and continues. Re-run until it prints
`run complete`.

Figures and tables need no GPU and no checkpoints — they read the JSON/JSONL artefacts —
so you can iterate on them locally while Kaggle trains.

## Verifying faithfulness

```bash
git clone --depth 1 https://github.com/facebookresearch/ijepa reference/ijepa
```

Loading the reference implementation's `state_dict` into `src/model/jepa.py` requires **no
key remapping** and reproduces its loss to all printed digits (activations differ only at
fp32 epsilon, from `scaled_dot_product_attention` vs an explicit softmax). The LR, weight
decay and EMA momentum schedules in `src/utils/schedulers.py` are bitwise identical to the
reference's stateful schedulers.

Deliberate, documented deviations:

| Change | Why |
|---|---|
| Block positions sample from `[0, H-h]` inclusive | The reference's exclusive bound means a block can never touch the bottom/right edge. Cosmetic on ImageNet; not on endoscopy, where polyps sit against the frame edge. |
| `scaled_dot_product_attention` | Same math, less activation memory on a 16 GB T4. |
| Correct `interpolate_pos_encoding` | The reference version assumes a class token these models do not have. Needed for the 224 → 352 transfer at fine-tuning. |
| Predictor width 192 (not 384) | Ratio-faithful: the paper uses predictor/encoder = 384/768 for ViT-B. Copying the absolute 384 would put a ViT-B-sized head on a ViT-S body. |
| `min_keep` validated at construction | On a small grid the reference's retry loop can spin forever with no output. That would silently burn a 9-hour session. |

## Protocol notes

These are enforced in code, not by discipline, because each is a common source of
inflated numbers:

- **Metrics at native resolution.** Logits are upsampled to the original H×W and
  thresholded there. Scoring at 352² against a downsampled mask inflates Dice ~1–2 points.
- **Test scored exactly once.** `evaluate_test` refuses to run before training completes,
  so "best test Dice over epochs" is unreachable.
- **Group-aware splits.** Kvasir-SEG contains near-duplicate frames from the same
  procedures; perceptual-hash components are kept whole within a split.
- **Pretraining de-contamination.** `scripts/dedup_phash.py` removes HyperKvasir frames
  that near-duplicate any Kvasir-SEG image, and reports the count.
- **Validation is deterministic** — its own dataset object with the eval transform, never
  a `Subset` of the augmented training set.

Two limitations to state rather than hide: a fixed 100-epoch budget structurally
disadvantages **MAE** (which keeps improving to 800+ epochs), and a global batch of 512
disadvantages **SimCLR** (which benefits from much larger batches). Both are the price of
holding the compute budget equal, which is the right fairness call.

## Kaggle notes

- **Request GPU T4 x2.** SimCLR and MoCo v3 abort on a single GPU rather than silently
  halving the global batch — InfoNCE is batch-coupled, so gradient accumulation cannot
  substitute. I-JEPA and MAE absorb it via `accum_steps`.
- T4 is sm_75: **fp16** tensor cores, no bf16 hardware. Precision is chosen from the
  detected compute capability; a P100 (sm_60) runs ~2× slower but is not fatal.
- Put `KAGGLE_USERNAME` / `KAGGLE_KEY` in **Add-ons → Secrets**. Never commit
  `kaggle.json` — it is gitignored, and rotate the token if it has ever been exposed.
- Only `/kaggle/working` persists within a session (20 GiB cap); `/kaggle/tmp` has ~60 GiB
  of scratch that does not count against it. Across sessions, nothing persists except
  Kaggle Datasets and committed kernel output — hence the checkpoint pusher.
